DWSIM 9.0.5 連携調査

PSE-RepairBench 実装メモ。調査時点: 2026-05-12。対象環境: Windows 上の DWSIM 9.0.5。

結論

この研究で必要な DWSIM 連携は、単なるファイル変換ではなく、観測抽出、故障注入、修復適用、再計算、 評価の縦通し pipeline を安定して回すことにある。第一実装は .NET Automation3 を中核に置き、 .dwxmz / .dwxml の直接解析は観測抽出の補助として使う。DWSIM の -commandline モードは、Property ID で指定できる値の読み書きには有用だが、今回の修復空間全体を表す主経路にはしない。

今回の研究で必要な DWSIM 連携

PSE-RepairBench は LLM に DWSIM flowsheet を直接編集させるのではなく、観測 JSON と structured repair action を介して診断と修復を評価する。そのため DWSIM との連携は次の役割に分かれる。

役割 必要な操作 主な出力 推奨経路
環境検出 DWSIM の実行ファイル、DLL、バージョン、利用可能な UI/Automation を確認する。 再現性 metadata、runner 設定 readme.txt、DLL assembly version、固定設定ファイル
観測抽出 flowsheet から topology、parameters、simulator log、stream table を抽出する。 topology.json、parameters.json、log.txt、streams.csv .dwxmz / .dwxml 直接解析 + Automation3 で補強
故障注入 base flowsheet に controlled fault を適用し、faulty flowsheet を保存する。 faulty flowsheet、oracle metadata、gold repair action Automation3 を基本にし、単純な構造確認は XML diff で監査
修復適用 LLM の structured repair action を DWSIM オブジェクトへ適用する。 repaired flowsheet、executor log Automation3 の IFlowsheet と unit operation API
再計算 修復済み flowsheet を DWSIM solver で実行し、収束・エラー・ログを取得する。 convergence status、error message、messages log Automation3 の CalculateFlowsheet と message listener
評価 stream result、purity、balance residual、duty などを抽出し、success criteria と照合する。 metrics report Automation3 経由の結果取得 + 抽出済み CSV/JSON

ローカル DWSIM 9.0.5 環境

このワークスペースで確認できた DWSIM 配置は以下の通り。

インストール先 %LOCALAPPDATA%/DWSIM
Classic UI %LOCALAPPDATA%/DWSIM\DWSIM.exe
Cross-Platform UI %LOCALAPPDATA%/DWSIM\DWSIM.UI.Desktop.exe
Automation DLL DWSIM.Automation.dll、assembly version 9.0.5.0
Interfaces DLL DWSIM.Interfaces.dll、assembly version 9.0.5.0

COM 登録補助 automation_reg.bat と automation_unreg.bat が配置されている。

DWSIM 公式サイトでは open source release として v9.0.5 が示されている。公式 API Help は現行 API の参照には有用だが、 ページによって assembly version が新しい系列を指すため、実装時はローカル DLL の version と runtime behavior を最終確認する。

連携方式の比較

方式 この研究での位置づけ 強み 制約・注意
第一候補
.NET Automation3		 修復適用、再計算、solver feedback 取得の主経路。 LoadFlowsheet、CalculateFlowsheet、SaveFlowsheet を持つ。 IFlowsheet 経由で simulation objects、graphic objects、messages、results にアクセスできる。 .NET 参照と DWSIM 配置ディレクトリの解決が必要。API Help と 9.0.5 DLL の差分は smoke test で固定する。
補助
.dwxmz / .dwxml 直接解析		 観測抽出、監査、diff、leakage check の補助経路。 既存の scripts/build_instances/prepare_dwsim_seed.py と整合する。 .dwxmz は ZIP として展開でき、SimulationObjects と GraphicObjects を解析できる。 DWSIM 内部モデルを完全には再現しない。保存形式の細部を直接編集する修復 executor は壊れやすいため避ける。
限定用途
-commandline XML 入出力		 Property ID で表せる stream/property の読み書きや小規模な外部最適化に使える。 DWSIM が simulation file と input XML を読み、指定された output XML に値と単位を書き出す。 -simfile、-input、-output の CLI 引数がある。 Property ID が必要。Topology 変更、column feed stage、unit-specific な複雑操作には Automation3 の方が自然。
副候補
COM Automation		 Windows/Excel/VBA 連携には有用だが、研究 pipeline の主経路にはしない。 DWSIM は COM/.NET Automation を公開しており、installer または batch file で COM 登録できる。 Windows 依存が強い。.NET から直接 DLL 参照する方が移植性と CI 化で扱いやすい。
周辺候補
TCP/IP Server		 長期的に headless backend 化を検討する候補。 リポジトリには DWSIM.Apps.TCPServer が存在し、ローカル配置にも TcpComm.dll がある。 9.0.5 での公開プロトコル、起動方法、安定性を追加検証するまで v1 実装には採用しない。
周辺候補
Python / CAPE-OPEN		 個別の拡張や thermo/unit operation 連携の候補。 DWSIM は Python scripting、CAPE-OPEN、外部 property package 連携を持つ。 今回の benchmark runner では、まず Automation3 で flowsheet 全体の実行制御を確立する。

推奨アーキテクチャ

  1. DWSIM runner layer: DWSIM.Automation.Automation3 を読み込み、flowsheet の load、calculate、save、release を担当する。
  2. Observation extractor layer: 既存の XML/ZIP 解析を維持しつつ、DWSIM 実行後の stream values、solver log、IFlowsheet.MessagesLog を補う。
  3. Repair executor layer: schemas/repair_action.schema.json の action vocabulary を DWSIM API 呼び出しへ変換する。
  4. Evaluator layer: success_criteria に基づき、収束、fatal error、purity、balance residual、duty 上限を判定する。

初期 action の実装順

最初の vertical slice は set_unit_parameter だけを実装対象にする。DWSIM の DWSIM.UnitOperations.UnitOperations.Column には feed stage を設定する API があり、 9.0.5 のローカル XML documentation でも SetStreamFeedStage 系の method が確認できる。 これを使って distillation_001_feed_stage_single の gold repair を実行する。

実装上の注意点

  • Object reference 解決: executor は repair action の target.guid を最優先にし、失敗時のみ name、tag へ fallback する。
  • Locale 固定: CLI や GUI 設定は decimal separator の影響を受ける可能性がある。runner は en-US 相当の数値表現を固定する。
  • Log leakage: simulator log は benchmark label、file path、gold repair を直接示す文字列を除去して公開 observation に入れる。
  • Release 判定: 現在の seed は unfaulted_placeholder_until_fault_injection flag を持つため、DWSIM 連携実装後に release profile を通すには実故障注入が必要。
  • API Help とローカル DLL の差: 公式 API Help は最新系列を指す場合がある。実装では 9.0.5 DLL で compile/run する smoke test を基準にする。

次に作るべきもの

優先度 成果物 目的 受け入れ条件
1 Automation3 smoke test DWSIM 9.0.5 DLL をロードし、sample または seed flowsheet を読み込んで計算できることを確認する。 load、calculate、solved/error message、save が CLI から再現できる。
2 set_unit_parameter executor 最初の distillation seed の gold repair を structured action から DWSIM API に適用する。 faulty copy に feed stage 変更を適用し、repaired flowsheet を保存できる。
3 run result extractor 計算後の stream table、messages log、balance indicators を metrics 用に抽出する。 streams.csv と metrics JSON に有限値、収束状態、主要 purity/duty が入る。
4 release validation update プレースホルダ seed から実故障注入済み seed へ移行する。 release --require-files で placeholder flag 由来の失敗が消える。
